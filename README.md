# Mothaf

An interactive virtual tourism and cultural experience platform for
archaeological sites, museums, landmarks, festivals and exhibitions.

It is an **engine, not a website**. One deployment powers many destinations.
The Roman Theatre of Jableh is the first experience it runs, and it exists
entirely as seed data — no file in `src/` mentions it, and no code path branches
on a specific destination.

---

## Quick start

```bash
npm install
cp .env.example .env.local   # then fill in the two secrets it names
npm run db:migrate
npm run db:seed              # prints a generated admin password once
npm run dev
```

Then open `http://localhost:3000` — you will be redirected to `/ar` or `/en`
depending on your browser's language.

| Where | What |
|---|---|
| `/ar` · `/en` | Home, with a live drifting panorama |
| `/ar/destinations/roman-theatre-jableh` | Destination page |
| `/ar/tour/roman-theatre-jableh/virtual-tour` | The tour |
| `/ar/admin` | Administration |

Development runs on **PGlite** — real Postgres compiled to WebAssembly, in
process — so there is no database to install. Production uses a normal Postgres
server; both speak the same dialect and run the same migrations.

## How it fits together

```
Visitor  ──►  /[locale]/(site)/…      browse: home, destinations, events
              /[locale]/(immersive)/… the tour, full viewport, no chrome
Editor   ──►  /[locale]/admin/…       console

              ── HTTP layer (thin route handlers, Server Actions) ──
              ── Domain services (business rules + authorization) ──
              ── Repositories (Drizzle) · Media · Auth · Analytics ──
              ── Postgres  ·  Storage driver (local | s3) ──
```

Arrows point one way. A route handler containing a business rule is a bug.

**Content model.** `Destination → Tour → Scene → Hotspot`, with points of
interest, media and events attached, and every piece of prose in a sibling
`*_translations` table keyed `(id, locale)`. Adding a language is an `INSERT`,
never a migration.

**Three extension seams**, each the only place a new capability is wired: the
renderer registry (`src/lib/tour/renderers`), the hotspot action registry
(`src/lib/tour/actions.ts`), and the storage driver
(`src/server/media/storage`).

Full detail in [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Notable decisions

**The panorama renderer is hand-written.** A 360° photo is one textured sphere
and one camera — about 400 lines of WebGL. That is 27 KB bundled, against
roughly 600 KB for a general-purpose 3D library whose scene graph, material
system and loaders would all go unused. Writing it also exposes the projection
matrix, which is what lets hotspots be real focusable DOM elements rather than
shapes painted into a canvas.

**Arabic is the default locale.** RTL is therefore the path exercised
constantly, not a mode someone remembers to check before release. Plural forms
go through `Intl.PluralRules` (Arabic has six categories, including a dual),
and dates use `ar-SY`, so the month reads أيلول rather than سبتمبر.

**Typefaces are vendored.** `next/font/google` fetches at build time, which
makes every build depend on a third party being reachable — it failed exactly
that way once during development. `public/fonts` is generated by
`scripts/vendor-fonts.mjs`. A page load now makes zero third-party requests.

**Visitor reads cache at the data layer, not the page.** Prerendering content
pages at build would mean the build system needs production database
credentials. Caching the queries instead keeps the build hermetic and lets a
publish invalidate by tag rather than waiting out a timer.

**Uploads are re-encoded, never stored as received.** The stored bytes are
pixels we rendered, so EXIF (including GPS), embedded thumbnails and any
polyglot payload appended after the image data are gone by construction.
